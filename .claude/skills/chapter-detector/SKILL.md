# chapter-detector — チャプター/投稿単位の判断

無音・フィラーをカット済みの勉強会動画に、YouTubeのチャプター（目次）を付ける。話題のまとまりを読み取り、視聴者が後から探しやすい粒度で章を区切り、簡潔なタイトルを付ける。長い収録は内容の大きな切れ目で複数の投稿（動画）に分けることもある。

## 入出力（ファイル経由）

- **入力**: 発話TSV（引数パス）。各行 `idx<TAB>mm:ss<TAB>speaker<TAB>text`。idx は発話の通し番号。
- **出力**: 決定JSON（指定パス）。形式は厳密に:

```json
{
  "chapters": [
    {"utt": <章が始まる発話idx>, "title": "章タイトル", "section_title": null, "is_required": true}
  ],
  "post_units": [
    {"title": "投稿タイトル", "chapters": [0,1,2]}
  ]
}
```

- `utt`: その章が始まる発話の idx（入力に存在するもの）。
- `title`: 12〜25文字程度の簡潔な日本語。内容を表す（「〇〇の設定方法」「△△について議論」等）。体言止め推奨。
- `section_title`: 大きなセクションの先頭章だけに付ける（例「環境構築」「ハンズオン」）。それ以外は `null`。
- `is_required`: 本編に必須なら true。雑談・脱線・休憩など任意なら false。
- `post_units`: 章を投稿単位にまとめる。`chapters` は **chapters配列のインデックス**（utt ではない）。通常は全章を1単位に。明確に独立した2テーマなら2単位に分ける。

## 手順

1. 入力TSVを Read で全件読む。
2. 話題の変わり目を見つけ、各章の開始 utt を決める。最初の章は冒頭(idx 0付近)から。
3. 章ごとに簡潔なタイトル。大きな話題の節目には section_title。
4. 投稿単位を決める（基本1つ。長大で独立テーマが2つなら2つ）。
5. 出力JSONを Write で書く。

## 粒度の目安
- 章は **2〜8分に1つ**が目安。短すぎ（30秒刻み）も長すぎ（全体1章）も避ける。
- 25分の収録なら概ね 4〜8章。
- 冒頭の挨拶/雑談は短い導入章（is_required=false でも可）にまとめてよい。

## 注意
- idx は入力に存在するものだけ。創作しない。
- 出力はJSONのみ。前置き・所感を書かない。
- タイトルは内容ベース。「チャプター1」のような無意味な連番にしない。
