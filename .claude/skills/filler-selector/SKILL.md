# filler-selector — フィラー意味判断

会話録画の自動編集で、**意味のないフィラー（言い淀み）だけ**を削除するために、抽出済み候補を一件ずつ意味的に判断する。文字列規則では「なんか」が口癖か「何か」の意味かを区別できないため、文脈を読んで人間の編集者のように判断する。

## 入出力（ファイル経由・コンテキストに本文を載せない）

- **入力**: 候補TSV（引数で渡されるパス）。各行 `id<TAB>speaker<TAB>context`。`context` の `【】` 内がフィラー候補で、前後が文脈。
- **出力**: 決定JSON（指定パス）。形式は厳密に `{"cut": [<削除するid>, ...]}`。**それ以外のキー・説明文は書かない**。

## 手順

1. 入力TSVを読む（`Read` か、大きければ `wc -l`/分割読み）。
2. 各行について、`【】` 内が**削除すべき意味のないフィラーか**を文脈で判断する。
3. 削除すると判断した `id` だけを集め、出力パスへ `{"cut":[...]}` を書く（`Write`）。

## 判断基準

**削除する（cut に入れる）= 意味的に無価値な言い淀み:**
- 純粋なためらい・つなぎ: `えー` `えーと` `えっと` `あのー` `んー` `うーん` `そのー` `あー`（発話の頭・切れ目で、内容に寄与しない）
- 同じ言い淀みの連続。

**残す（cut に入れない）= 内容や対人機能を持つ:**
- 実語として意味がある: `あの`(あの人/あの件)、`その`(その方法)、`なんか`(=何か、具体物を指す)、`ええ`(=はい、肯定・相槌)、`まあ`(譲歩・結論導入で意味がある時)。
- 文の途中で文法的に必要なつなぎ。
- 判断に迷うものは**残す（保守的に）**。誤って実発話を削るより、フィラーが少し残る方がよい。

## 例

```
id  speaker        context
12  mossan-hoshi   今日は【えーと】そのですね、コードを
13  mossan-hoshi   【なんか】良い方法ないですかね
14  taniguchi      はい、【ええ】わかりました
15  mossan-hoshi   設定は、【えー】ここをこうして
```
→ `{"cut": [12, 15]}`（13の「なんか」=具体を指す/口癖判断が割れる→残す、14の「ええ」=肯定の相槌→残す）

## 注意
- `id` は入力に存在するものだけ。創作しない。
- 出力はJSONのみ。Claudeの所感や前置きをファイルに書かない。
