# Deep Research 依頼プロンプト: 自動フレーミング（クロップ）モデルの選定

> 用途: 下のブロックをそのまま Deep Research 系LLMに貼って実行する（Claudeでは回さない運用）。
> 目的は「この小規模・単一ドメインのアノテ済みデータに最適なクロップ予測モデル/手法の選定」。

---

## 依頼プロンプト（ここから貼り付け）

```text
あなたはコンピュータビジョンの実装に詳しいリサーチャーです。以下のタスクに最適な**モデル/アーキテクチャと学習レシピ**を、最新（2024–2026）の研究・実装を踏まえて選定・比較してください。結論は「RTX 2070 (8GB) / Windows / Python3.11 / PyTorch2.6 で実際に学習・推論できる」具体策に落としてください。

### タスク
デスクトップ画面録画（勉強会の収録、1920×1080）の各「安定シーン」を代表する1フレームを入力に、自動フレーミングのための出力を予測する:
1. **no_crop か crop か**の二値（全画面のままか、寄せるか）。
2. crop の場合の**正規化 bbox `[x0,y0,x1,y1]`**。出力契約は**アスペクト比(16:9)を維持したクロップ枠を1個**返すこと。
   ※モデル内部の回帰表現（4座標直接 / 中心+サイズ / アンカーオフセット等）は**実装詳細として提案側に委任**（出力が上記bboxになればよい）。

出力はシーン単位（数百フレーム/動画に対し数十シーン）で使い、そのシーン区間に静的な crop+scale として適用する。**毎フレーム推論ではない**ので推論コストは緩いが、学習データは小さい。

### 入力画像の性質
- 1920×1080 のデスクトップ画面キャプチャ。内容はブラウザ（調査レポート/論文）、IDE、スライド、ターミナル、ビデオ通話の画面共有など多様。
- マウスカーソルが写る。ウィンドウのchrome（タブ/タスクバー/余白）が含まれることが多く、「メイン内容領域」はその中の一部。
- 同一クリエイターの収録に限定（単一ドメイン）。配色・レイアウト傾向は近い。

### タスク上の事実: 切り抜き領域はマウス位置に影響される
- 正解の crop 領域は、その場面で**マウスがある/動いている位置に影響される**（編集者は作業箇所を画に残す。カーソルは正解枠に約83%入る）。
  ただし**マウスだけでは決まらない**（画面内容も効く）。これは label を理解するための背景事実。
- ⚠️ これは「マウスを事前抽出して別入力に渡せ」という意味では**ない**。カーソルは画面に写っているので、
  生フレームから一発で crop を出すモデルが暗黙に汲んでもよいし、明示的に座標を使ってもよい。
  **入力の構成・特徴抽出の有無・段階構成は一切前提しない。最適な設計は提案側が決める。**

### 教師データ（同一クリエイターの実編集.drpを正解とし人手アノテ）
- **人手アノテ済みの有効サンプル ~351件**（補正423 − 却下72）、**32本の録画**にまたがる。内訳 crop 342 / no_crop 9。
  - ※この抽出は寄せ(crop)クリップ中心のため no_crop が少ない。**no_crop↔crop 二値**用には no_crop 例を含む別セット（~84件: no_crop 26 / crop 58）も併用可。
- ラベル: 正規化 bbox `[x0,y0,x1,y1]`、`no_crop`(bool)、`zoom`(倍率)。
- **分布の実測（crop 342件）**:
  - 中心x: med 0.51 / sd **0.09**、中心y: med 0.53 / sd **0.11** ← 中心は中央寄りだが分散あり。
  - 幅: med 0.70 / sd **0.17**、zoom: **1.06–6.58 / sd 0.66** ← 寄せ量(サイズ/ズーム)が大きく変動（最大6.6倍）。
  - 含意: 中心も多少動くが、特に**「どれだけ寄せるか」がコンテンツ依存で大きく変わる**。サイズ/ズームの予測が肝。
- 単一フレーム特徴での素朴な凍結埋め込み回帰/ヒューリスティクスは **IoU ≈ 0.62 で頭打ち**だった（要・超え）。カーソルは83%の確率で正解bbox内だが中心は決めない。
- **未ラベル素材**: 追加の未ラベルは「動き/シーン変化でdedupした異なる画面状態」で実測 約80–100/録画 ×32本 ≈ **2千強の異なるシーン**程度（生fps抽出は近重複だらけで無意味なので除外）。
  ただし**学習の主データはあくまで上記アノテ済み351件**。未ラベルは自己教師あり/ドメイン適応の補助に使える“あれば程度”で、過大評価しないこと。

### 制約
- ⚠️ **商用システムである。商用利用可能なライセンスのモデル・事前学習重み・データセット・ライブラリのみを調査・推奨対象とする。**
  AGPL（例: Ultralytics系）/研究用限定/CC-BY-NC/non-commercial 等は**最初から除外し、検討にも挙げないこと**（無価値）。
  挙げる候補は全て商用クリーンであることが前提。各候補にライセンス名を併記すること。
- ハード: Windows 11 / RTX 2070 8GB VRAM / Python 3.11 / torch 2.6 (cu124)。学習も推論もローカル。
- 中小データ(ラベル~350、未ラベルは多数)。**転移学習・データ拡張・自己/半教師あり**で過学習を避ける戦略が必須。
- Windowsでの依存衝突(例: PaddleOCR系のDLL問題)を避けられる実装を優先。ONNX化できると尚良。

### 評価指標の優先順位（順位付けの主軸）
- ①**true-crop区間の bbox mean IoU** と ②**no_crop↔crop の二値精度** を**同等に重視**。
- **過剰クロップ（寄せすぎ / no_crop を crop と誤判定）は最も視認される破綻**なので、タイブレーク兼ガードレールとして回避する。
  ただし「常に no_crop＝安全側」は目的(寄せること)に反するので不可。

### 答えてほしいこと（手法は限定しない。空間を網羅的に調べて推奨を出すこと）
1. **このタスク・このデータ規模に最適なモデル/手法**を、取りうる選択肢を**あなたが網羅的に洗い出して**比較・順位付けし、推奨を出すこと（特定の系統に限定しない）。各案の長所/短所と、この小データ・スクショ系ドメイン・上記ラベル分布での妥当性を示す。
2. 推奨手法の**学習レシピ**（事前学習元、データ拡張、過学習対策、交差検証、ハイパラ）と**期待精度(IoU等)・リスク**。
3. **中小データ(ラベル~350)で精度を出すための戦略**（転移学習・自己/半教師あり・合成データ・未ラベル自フレーム活用など、有効なものを提案）。
4. **推論**: 推奨手法のローカル(RTX2070)での学習可否・推論レイテンシ、ONNX化の可否。
5. 参考文献/実装リポジトリ/事前学習重みのリンク（**全て商用可・ライセンス名併記**）。

専用モデルを学習する方針は確定済み。**やるか否かではなく、どう作るのが最善か**に集中すること。
無理に1つへ絞らず、有力な選択肢を**根拠とトレードオフ付きで順位付け提示**せよ（最終選択はこちらで行う）。
```

## このプロンプトを書いた背景（社内メモ）
- 当初依頼＝専用クロップモデルの学習。アノテはその教師データ。モデル選定は実装側(私)に一任、
  選定に調査が要るならLLM向け調査依頼プロンプトを書く運用（[[deep-research-cost-workflow]]）。
- 実データ分布から「中心は中央寄りだがズーム量が大きく変動(最大6.6倍)」が判明。固定箱はズーム変動を捨てる劣化案。
- 旧「crop枠は学習不能」結論は単一フレーム凍結埋め込みの弱いprobe由来で、撤退は私の独断ミス。

## 学習データの所在（永続化済み・2026-06-26）
- **`data/framing_anno_full/`**: 人手アノテのフル集合。`dataset.json`(475件・有効アノテ351=corrected&not rejected) + `frames/`(425枚)。
  一時領域 scratchpad/feas_train から退避したもの。**これがクロップモデル学習の正データ**。
- 既存 `data/framing_ds*`(134/84)は別抽出の部分集合（no_crop例を含むのでno_crop/crop二値の補助に使える）。
